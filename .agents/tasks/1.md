## Key Decisions
- `dev`가 개발 통합 및 기본 브랜치다. workflow_run은 기본 브랜치의 workflow만 실행하므로 main 최초 승격 전 자동화 교착을 방지한다.
- `main`은 정식 승격 전용. 일반 웹 merge/직접 push 대신 dev의 성공 CI SHA를 고정해 명시 workflow로 merge commit과 정식 태그를 atomic push한다.
- 승격 키는 `main-promotion` environment에만 저장하고 dev 실행으로 제한한다. GitHub DeployKey ruleset 예외는 개별 키가 아닌 deploy key actor 종류에 적용된다. 다른 write deploy key 추가 시 권한 재검토가 필요하다.
- 초기 main은 master SHA를 보존하며 새 유입에만 태그 요구를 적용한다.
- 새 GitHub Release 자동 발행 연동은 제외. 기존 수동 발행 경로는 기존 태그를 읽기만 하도록 변경한다.
