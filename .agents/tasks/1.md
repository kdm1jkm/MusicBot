## Key Decisions
- `dev`가 개발 통합 및 기본 브랜치다. workflow_run은 기본 브랜치의 workflow만 실행하므로 main 최초 승격 전 자동화 교착을 방지한다.
- `main`은 정식 승격 전용. 일반 웹 merge/직접 push 대신 dev의 성공 CI SHA를 고정해 명시 workflow로 merge commit과 정식 태그를 atomic push한다.
- 승격 키는 `main-promotion` environment에만 저장하고 dev 실행으로 제한한다. GitHub DeployKey ruleset 예외는 개별 키가 아닌 deploy key actor 종류에 적용된다. 다른 write deploy key 추가 시 권한 재검토가 필요하다.
- 초기 main은 master SHA를 보존하며 새 유입에만 태그 요구를 적용한다.
- 새 GitHub Release 자동 발행 연동은 제외. 기존 수동 발행 경로는 기존 태그를 읽기만 하도록 변경한다.

## Unresolved Issues & Handoff
- 이전 정책에서 수리 3회를 수행했다(승격 CI failed-jobs-only 처리; 테스트 자식 stdout UTF-8; 사용자 승인 Windows Unicode-native fixture). 사용자 지시로 고정 횟수 한도와 소진 중단 규칙은 제거했다. 이후에도 진단·변경·검증 이력을 보존하며 actionable 실패는 계속 수정한다.
- feature PR은 인간이 dev에 merge한다. 에이전트 자동 merge 금지.
- merge 전에는 원격 dev 자동화 end-to-end를 실행할 수 없다. 로컬 실제 Git 및 API fixture smoke와 PR CI 증거를 제공하며, GitHub 이벤트 기반 beta 발행·environment deploy key 승격은 인간 merge 후 확인해야 한다. 검증 결과와 최종 상태는 PR/Issue 인계 comment를 함께 참조한다.
- Deno packaged smoke 실패는 로컬 실제 실행과 코드 HEAD Windows hosted CI에서 모두 해결됐다. 현재 알려진 코드/CI 실패는 없다. 전체 spec의 남은 실환경 경로는 인간 merge 후에만 실행 가능하므로 human dependency로 기록한다. 필요한 사용자 작업: PR #2를 dev에 merge한 후 실제 dev CI→beta 발행을 확인하고, 정식 승격이 필요하면 Promote Main을 명시 실행한다. 이 외부 조건이 해소되기 전에는 전체 PASS 대신 사유 있는 대기 상태로 남긴다.
- CI가 모두 통과한 뒤에만 사람이 PR #2를 dev에 merge한다. 해당 dev push의 두 CI job 성공과 beta 태그를 확인한다. 정식 승격을 원하면 dev에서 Promote Main에 버전과 전체 dev SHA를 입력하고 main 둘째 부모·정식 태그 SHA 일치를 확인한다. 에이전트 임의 merge/정식 승격 금지.
